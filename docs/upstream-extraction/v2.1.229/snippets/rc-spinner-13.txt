# densable 2.1.229 #13 — RC clients stuck working spinner after laptop slash
# SEA: /tmp/official-229/plat/package/claude
# Changelog: "Fixed Remote Control clients showing a stuck working spinner after a slash command typed in the laptop terminal"
#
# Verdict: GOLD FOUND — product surface multi-part; local largely HAVE / beyond densable
# (not pure UNKNOWN; not a clean 1:1 missing symbol to invent-land)
#
# Product bug class:
# Laptop types a slash (often local / local-jsx, shouldQuery:false). Hidden scaffolding
# messages (`<local-command-caveat>`, local-command-stdout/stderr, meta caveat) still
# flow over the bridge. If worker_status stays `running` (or UI `working` stays true)
# after the command completes, RC clients keep the working spinner.
#
# densable fix surface (multi-part, no single string "stuck spinner after slash"):
#  1) REPL derives `working` only from isQueryActive (r_h / DBa); local-jsx forces waiting, working:false
#  2) remote-bridge only Un("running") when filtered msgs pass fCo AND no pending permission map
#  3) sendResult() forces Un("idle") + result event (k0s)
#
# Local already has richer scaffolding filter + result deferral for this class.
