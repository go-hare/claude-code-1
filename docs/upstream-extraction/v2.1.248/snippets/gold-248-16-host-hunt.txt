## Why AgentView is still not a host

Official #16 is not "any UI that lists jobs". It is:
1. a subscribe/getSnapshot store field prStatuses: Map<href, RJt>
2. load on first attachView when size===0
3. persist when that field identity changes
4. fetch batch writes + FleetView rp() reads the same Map

Leftover AgentView already split #O (terminalHolders) and a different PR
probe (prViewCache). It does not already hold an RJt Map and has no
natural leftover store object next to jobs (no Fh() snapshot).
Inventing class gc or a fake prStatuses useState that nothing official-shaped
reads/writes is banned.
