# densable 2.1.218 — AUDIT #16 PR events lost on immediate exit

Official: Fixed pull request events occasionally being lost when a session exited immediately after creating or linking a PR.

Binary: /tmp/official-218/plat/package/claude (2.1.218)

## densable symbols

| densable | meaning |
|---|---|
| `Lt.pendingPrLinks` / `eNn()` (`getPendingPrLinks`) | process-global `Set` of in-flight PR-link promises |
| `But(promise)` | track a pending PR-link promise in the set; swallow rejections; remove on settle |
| `DZr()` | flush pending PR links: `NFr(Promise.allSettled([...e]), xv_)` with `xv_=2000` ms |
| `IZr(prInfo)` | emit optional `code_change_published` system event + `await linkSessionToPR(...)` |
| `hOy` (`linkSessionToPR`) | `await Qee(...)` async append of `pr-link` transcript entry + analytics + cache |
| `Hbo(pr, repo?)` | `gh pr view --json url` resolve then `IZr` |
| `Ubo` | densable `trackGitOperations` equivalent (success-path git/PR tracking) |
| `NFr(promise, ms)` | race promise vs timeout (resolve void on timeout) — does not reject |
| call sites of `await DZr()` | engine teardown after turn drain; print.ts session cleanup before done |

## densable control flow (1:1)

1. On successful `gh pr create` / other PR actions / `gh pr checkout` / bare `git push` / glab/curl PR create, schedule link work via `But(...)` instead of fire-and-forget.
2. `But(p)`: `t=eNn(); r=p.catch(()=>{}); t.add(r); r.finally(()=>t.delete(r))`
3. Immediate exit previously raced dynamic import + async append before process teardown finished, dropping `pr-link` / linked-session metadata / contribute-link side effects.
4. Fix: before process/session cleanup completes, `await DZr()` so in-flight PR link promises settle (cap 2000ms).
5. `linkSessionToPR` itself is async (`await Qee` append) and records write failure via `V2t("pr_link", ...)`.
