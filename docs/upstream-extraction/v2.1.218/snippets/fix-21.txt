### Root cause of the "doomed with large thinking budget" loop

Older local (pre-fix) logic effectively did:

```ts
const minRequired =
  (thinkingConfig.type === 'enabled' ? thinkingConfig.budgetTokens : 0) + 1
const adjustedMaxTokens = Math.max(FLOOR_OUTPUT_TOKENS, availableContext, minRequired)
retryContext.maxTokensOverride = adjustedMaxTokens
// always continue — no no-progress guard
```

When `budgetTokens` (large thinking) > `availableContext`, override becomes
`budgetTokens+1` again → next attempt is **identical** to the doomed request →
infinite retry until maxRetries (or worse under persistent mode).

densable 2.1.218:
1. Sets `maxTokensOverride = availableContext` only (NO minRequired/thinking inflate).
2. If a previous override exists and new available is **not strictly smaller**,
   throw `"max_tokens overflow adjustment made no progress"` (stop doomed loop).

## B) Ctrl+B background shell caps (same path as other bg)

### densable symbols / needles
- `CLAUDE_SUBAGENT_BG_SHELL_MAX_MS` (env)
- `ZV_=3600000` (default 1h cap ms)
- `function fkd(e)` — resolve cap for agent-scoped shells
- `ShellCommand.background(e, t)` options: `{capMs?, skipSpill?}`
- `function Tsn` — mid-flight background of a single foreground shell
- `function a$e` — background ALL (`task_local_shell_background_all` / Ctrl+B)
- `function Ppt` / `spawnShellTask` — spawn-as-background already passes cap
- `function hkd` — keepalive + pressure reap (`releaseBgCap` bookend)

Key product rule:
- **Agent-scoped** background shells get wall-clock kill cap:
  `CLAUDE_SUBAGENT_BG_SHELL_MAX_MS || 3_600_000`.
- **Main-session** shells (`agentId === undefined`): `fkd` returns `undefined`
  → no cap timer (same as densable).
- **Monitor** kind: no cap on spawn path.
- Ctrl+B / `Tsn` / `a$e` MUST pass the same `{capMs: fkd(agentId)}` as
  spawn-as-background (`Ppt`), so agent shells cannot escape the cap via
  manual background.
