# densable 2.1.221 #10 — SDK MCP tools named constructor crash

Official: Fixed a crash when preparing API requests for SDK MCP tools named
after built-in object properties such as `constructor`.

## Confirmed local crash locus (go-hare, 2026-08-12)

`src/utils/api.ts` `filterSwarmFieldsFromSchema` → `toolToAPISchema`:

```ts
// BEFORE: plain Record
const fieldsToRemove = SWARM_FIELDS_BY_TOOL[toolName]
// SWARM_FIELDS_BY_TOOL['constructor'] === Object.prototype.constructor (Function)
// for (const field of fieldsToRemove) → TypeError: X is not iterable
```

Repro (Bun):

```
SWARM_FIELDS_BY_TOOL['constructor'] → [class Object] function, length 1
for…of → CRASH: {} is not iterable
```

This matches the official wording **preparing API requests** (tool schema assembly), not only MCP SDK registerTool.

## Local fix (go-hare product harden — 2026-08-12 「修」)

| Site | Change |
| --- | --- |
| `SWARM_FIELDS_BY_TOOL` | `Object.create(null)` + `Object.hasOwn` membership |
| `toolPermissionsFromClaudeAiTools` / `toolPermissionsFromSetServersTools` | null-proto maps |
| `client.ts` toolPermissions lookup | `Object.hasOwn` (no Function leak as permission) |
| tests | `toolToApiSchema.constructor.221.test.ts` + permission builder cases |

**Not patched (still densable/MCP-SDK residual):**

- Public `@modelcontextprotocol/sdk@1.29.0` `_registeredTools = {}` + truthy membership
- densable SEA `I_a` / `fVp` createSdkMcpServer registry (go-hare has no local twin)
