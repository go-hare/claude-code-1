## Release claim (#12)
Improved permission dialogs: display text and "don't ask again" options now
always match what a grant would cover, and "don't ask again" is withheld when
contents cannot be fully displayed.

## Schema / gold description
suppress_always_allow_rule / PermissionAskDecision.suppressAlwaysAllowRule —

True when the dialog must not offer the persistent "don't ask again" row for
this ask: accepting it would write a whole-tool allow rule broader than the
ask's own verb (PermissionAskDecision.suppressAlwaysAllowRule). Hosts
rendering approve options should omit any persistent-rule affordance when set.

@299152698 / @266599760 / @266599765 / gold-perm-withhold.txt

Wire field also sits beside matched_ask_rule / classifier_approvable /
requires_user_interaction on SDK permission request payloads
(@263205808, @294912569, @299219952).

## 1) PRODUCERS — where suppressAlwaysAllowRule is SET

### 1a. Artifact / shared-state asks (primary `:!0` sites)
Ask decisions that approve-for-session would cover a broader verb than the
dialog discloses set `suppressAlwaysAllowRule:!0` (often with localDisplayOnly).

Examples (@285605825+):
- First page-data read: approving covers every readable artifact for the session
- Artifact DB read/write (plan-mode / notification / Cowork surfaces)
- Artifact watch subscribe / re-watch
- Publish when base is symlink / plan-mode / Cowork: `...zq()&&{suppressAlwaysAllowRule:!0}` (@285641569)

Pattern:
```
return {
  behavior: "ask",
  message: "...",
  updatedInput: {...},
  suppressAlwaysAllowRule: !0,
  decisionReason: {...},
  localDisplayOnly: !0, // often
}
```

### 1b. Tool hook `suppressesAlwaysAllowRule(input)`
MCP/tool objects expose `suppressesAlwaysAllowRule: () => ldl(...)` /
`Vdl(...)` (@288567000, @288735921). Consumers OR this with the ask-field.

### 1d. Related withhold signals (display incomplete → one-time only)
Not always the same field, but same product rule ("don't ask again withheld
when contents cannot be fully displayed"):
