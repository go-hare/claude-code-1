=== settings schema (from SEA) ===
spellcheck: { enabled?, checker?, language?, color? }
Turn on spell checking of the prompt input (default: false)
Which spell checker to run: "aspell", "hunspell", "ispell", or "auto" (default) for the first of those found on PATH
Dictionary to use, passed to the checker as-is (aspell --lang, hunspell -d, ispell -d), e.g. "en_GB"; names are checker-specific (letters, digits and _ - . , only). Default: the checker's own default
Color of misspelled words (they are also underlined): a terminal color name such as "red" or "magenta", "#rrggbb", "rgb(r,g,b)", "ansi256(n)" or "ansi:<name>". Default: the theme's error color
Underline misspelled words in the prompt input as you type, using an installed aspell or hunspell/ispell (off unless "enabled" is true; does nothing if none is installed). Read from user, flag and managed settings only (the whole block from the highest-precedence of those applies); ignored in project .claude/settings.json and .claude/settings.local.json.

=== policy / tier messages ===
a spellcheck block in project or local settings is ignored, whatever else is configured; set it in your user settings (~/.claude/settings.json) instead
the spellcheck block in <tier> applies (as a whole, over any lower tier) and has no usable "enabled": true, so spell checking is off

=== backends / protocol ===
vKe=["aspell","hunspell","ispell"]
hs_=/^[A-Za-z][A-Za-z0-9_.,-]{0,63}$/
aspell args: -a --encoding=utf-8 --sug-mode=ultra [--lang=]
hunspell args: -a -i utf-8 [-d]
ispell args: -a [-d]
banner detect: "@(#) International Ispell" + "but really Aspell" / "but really Hunspell"
ispell pipe protocol parse: *|+|- correct; &|?|# misspelled
jTu = "!\n" (ispell terse/version handshake line)
